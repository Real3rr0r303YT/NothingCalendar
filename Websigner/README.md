## Features

- **One-tap OTA install:** uses Apple's native `itms-services` over-the-air installation.
- **Sign your own IPAs:** bring your own certificate and provisioning profile.
- **Anti-revoke friendly:** includes a NextDNS guide for blocking Apple's revocation checks.
- **Free and open source:** licensed under GPL-3.0.

## Installing the app (users)

1. Open the [landing page](https://real3rr0r303yt.github.io/WebSigner-iOS/) in **Safari** on your iPhone or iPad.
2. *(Recommended)* Set up the anti-revoke DNS first. See [below](#dns--anti-revoke-guide).
3. Tap **Install App** and confirm the prompt.
4. Go to **Settings → General → VPN & Device Management**, select the developer certificate and tap **Trust**.
5. If asked, turn on **Developer Mode** in **Settings → Privacy & Security**.

> OTA installs only work in Safari. Chrome, Firefox and in-app browsers will not trigger the install.

## Deploying your own copy (maintainers)

### 1. Enable GitHub Pages

1. Go to **Settings → Pages**.
2. Under **Build and deployment**, choose **Deploy from a branch**, then select your branch and `/ (root)`.
3. Your site will be live at `https://<username>.github.io/<repo>/`.

### 2. Build a correctly signed IPA

iOS only accepts an OTA install if the IPA is signed for the device. **Unsigned, Simulator and App Store-signed builds always fail with "cannot be installed at this time".**

**With Xcode:**

1. Select **Any iOS Device (arm64)** as the run destination. Don't select a Simulator.
2. Choose **Product → Archive**.
3. In the Organizer, click **Distribute App** and choose **Release Testing** (Ad Hoc) or **Enterprise**. Don't choose App Store Connect.
4. Export the IPA. For Ad Hoc, every target device's UDID must be registered in your Apple Developer account **before** the profile is generated.

**Packaging by hand (an already-signed `.app`):**

```bash
mkdir Payload
cp -R WebSigner.app Payload/
zip -qry WebSigner.ipa Payload   # -y keeps framework symlinks intact
```

The zip's top level must be `Payload/`. Don't edit anything inside the `.app` after signing, not even `Info.plist`, or the signature breaks.

**Check it before publishing:**

```bash
python3 tools/check_ipa.py WebSigner.ipa --udid <your-device-UDID>
```

This checks the archive layout, arm64 binary, code signature, profile type and expiry, App ID vs. bundle ID, extension bundle IDs, and whether your UDID is in the profile.

### 3. Publish it with the OTA release workflow (recommended)

1. Create a GitHub Release (e.g. tag `v1.0.1`) and attach the signed `.ipa`. It must be the release's only `.ipa`.
2. Publishing the Release triggers `.github/workflows/ota-release.yml`. It validates the IPA and rewrites `manifest.plist` with the exact bundle ID, version, title and tag-specific download URL, then commits it to the default branch.
3. Wait for GitHub Pages to redeploy, then install from the landing page.

You can also re-run it from **Actions → OTA release → Run workflow** with a tag.

### 3b. …or edit `manifest.plist` manually

Generate it locally:

```bash
python3 tools/check_ipa.py WebSigner.ipa --write-manifest manifest.plist \
  --ipa-url https://github.com/<username>/<repo>/releases/download/v1.0.1/WebSigner.ipa \
  --display-image https://<username>.github.io/<repo>/assets/icon-57.png \
  --full-size-image https://<username>.github.io/<repo>/assets/icon-512.png
```

Or replace every value marked `CHANGE ME` by hand:

| Key                  | Value                                                                    |
| -------------------- | ------------------------------------------------------------------------ |
| `software-package`   | Direct HTTPS URL of your signed `.ipa`.                                  |
| `display-image`      | 57×57 PNG icon URL.                                                      |
| `full-size-image`    | 512×512 PNG icon URL.                                                    |
| `bundle-identifier`  | **Must exactly match** the `CFBundleIdentifier` of the signed IPA.       |
| `bundle-version`     | **Must match** the version inside the signed IPA.                        |
| `title`              | App name shown in the install prompt.                                    |

### 4. Point the Install button at your manifest

In `index.html`, update the `href` of the `#install-btn` link. The manifest URL must be **URL-encoded**:

```html
<a id="install-btn"
   href="itms-services://?action=download-manifest&amp;url=https%3A%2F%2F<username>.github.io%2F<repo>%2Fmanifest.plist">
```

**Requirements for OTA installs:**

- The manifest **and** the IPA must be served over **HTTPS** with a valid, trusted certificate. GitHub Pages and GitHub Releases both qualify.
- The IPA must be signed with a certificate and provisioning profile valid for the target device (enterprise, ad-hoc with the device's UDID, or developer).

### Troubleshooting "Unable to install … cannot be installed at this time"

Run `python3 tools/check_ipa.py WebSigner.ipa --udid <UDID>` first. It catches most of these.

| Cause | Fix |
| --- | --- |
| `software-package` URL returns 404 (e.g. no Release yet, or the asset has a different name) | Publish a Release with the `.ipa` and let the workflow regenerate the manifest. Open the URL in a browser to confirm it downloads. |
| Manifest or IPA not on HTTPS, or Pages not enabled | Enable Pages (step 1) and open the manifest URL in Safari. It must load without a certificate warning. |
| Unsigned, Simulator or App Store-signed IPA | Re-export as Ad Hoc, Development or Enterprise (step 2). |
| Device UDID not in the Ad Hoc profile | Register the UDID, regenerate the profile, re-sign. |
| `bundle-identifier` in the manifest ≠ `CFBundleIdentifier` in the IPA | Regenerate the manifest from the IPA (step 3/3b). |
| Signing certificate expired or revoked by Apple | Re-sign with a valid certificate. DNS blocking can't revive a certificate that's already revoked. |
| App with the same bundle ID already installed from a different team (e.g. the App Store) | Delete the existing app first, or use a different bundle ID. |
| Device iOS is older than the app's `MinimumOSVersion` | Update iOS or lower the deployment target. |
| Opened in Chrome/Firefox or an in-app browser | Use Safari. |

To find a device's UDID, connect it to a Mac and click the serial number in Finder, or use a UDID-lookup profile site.

## DNS / Anti-Revoke Guide

iOS checks with Apple whether an app's signing certificate is still valid. If Apple has revoked it, the app will no longer open. Blocking those checks via DNS helps keep installed apps working.

1. Create a free account at [my.nextdns.io](https://my.nextdns.io/signup).
2. In the **Denylist** tab, add:
   - `ppq.apple.com` **(required)**
   - *Optional, stronger, may affect some Apple services:* `ocsp.apple.com`, `ocsp2.apple.com`, `crl.apple.com`, `valid.apple.com`
3. On your device, open [apple.nextdns.io](https://apple.nextdns.io) in Safari, enter your configuration ID and download the profile.
4. Install it via **Settings → General → VPN & Device Management**.
5. Check that it's working at [test.nextdns.io](https://test.nextdns.io). It should report `"status": "ok"`.

> ⚠️ Keep the profile enabled at all times, including on cellular. DNS blocking lowers the risk of revocation but cannot guarantee it won't happen.
